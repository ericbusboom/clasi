# 004-001: Add dotconfig as runtime dependency and verify import surface

## Description

`dotconfig` is already installed in the development environment (editable install
from the dotconfig project). This ticket makes that dependency explicit by adding
it to `pyproject.toml`'s `[project.dependencies]`, updating the lock file, and
confirming that `import dotconfig.versioning` succeeds in the clasi environment.

This ticket is the foundation for all downstream tickets — they depend on
dotconfig being importable.

## Acceptance Criteria

- [x] `pyproject.toml` lists `dotconfig>=0.20260507.2` in `[project.dependencies]`.
- [x] `uv lock` (or equivalent) is run to update `uv.lock` with the new dependency.
- [x] `python -c "import dotconfig.versioning; print('ok')"` succeeds in the
      project's virtual environment.
- [x] Full test suite passes (`pytest`) with no new failures.
- [x] No other file changes in this ticket.

## Implementation Plan

### Approach

Edit `pyproject.toml` to add the dotconfig dependency, then update the lock file.

### Files to Modify

- `pyproject.toml` — add `"dotconfig>=0.20260507.2"` to `[project.dependencies]`
- `uv.lock` — regenerated by running `uv lock` after editing pyproject.toml

### Steps

1. Open `pyproject.toml`. In `[project]` under `dependencies = [`, add:
   ```
   "dotconfig>=0.20260507.2",
   ```
   Position it alphabetically (after `click`, before `jinja2`) or at the end of
   the list — either is fine.

2. Run `uv lock` to regenerate `uv.lock`. If `uv` is not available, run
   `pip install -e .` to verify the dep resolves without error.

3. Verify: `python -c "import dotconfig.versioning; print(dotconfig.versioning.__file__)"`.

4. Run the full test suite: `pytest`. Confirm no new failures.

### Testing Plan

- `pytest` (full suite) must pass with the same result as before this change.
- The import check above is a smoke test; it is not a new automated test.

### Documentation Updates

None. The dependency addition is self-documenting in `pyproject.toml`.
