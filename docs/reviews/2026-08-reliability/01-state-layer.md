## Findings

**1. critical / correctness — `tools/artifact_tools.py:1259-1263` and `1808-1809`** — `close_sprint`'s DB update is wrapped in `except (ValueError, Exception): pass`. Scenario: any missing gate or phase mismatch during the advance-to-done loop → sprint directory archived, frontmatter `closed`, but DB keeps old phase **and the execution lock**; next sprint's `acquire_lock` fails with "lock held by sprint X" until someone hand-edits the DB — exactly the reported "weird unrelated bug" shape. Fix: transactional `StateDB.force_close(sprint_id)` (phase=done + lock delete), failures surfaced in close_sprint JSON.

**2. critical / correctness — `status/inconsistency.py:243-247` + `templates/sprint.md:4` + `sprint.py:498`** — Drift detection compares frontmatter `status:` (`roadmap`/`planning-docs`/`closed`) against sprint-machine state names (`open`/`planned`/…): sets disjoint except `closed`, so every healthy active sprint yields a permanent `state_drift` entry. The drift detector is drowned in structural false positives. Fix: one vocabulary (the machine's), every writer uses it, delete the others.

**3. critical / correctness — `schemas/state-machines/sprint.yaml:11-12,24-25` + `status/reporter.py:516-539`** — The sprint machine's `open` and `planned` states have **identical** invariants, and later states are cumulative supersets, so `evaluate_state`'s "exactly one state must match" contract (`evaluator.py:69-80`) is violated on essentially every evaluation; `AmbiguousStateError` is the *normal* path, and the reporter recovers the answer by regexing + `ast.literal_eval`-ing the exception message text. Scenario: reword the error message → status silently reports "unknown" everywhere. Fix: define "most-advanced matching state wins" in `evaluate_state` (it's a checklist machine, not an exclusive-state machine) and delete `_last_matching_state_from_error`.

**4. critical / correctness — `state_machine/predicates/sprint.py:96-98` + `state_db_class.py:55`** — `is_review_satisfied` requires a `sprint_review` gate that `record_gate` rejects (not in `VALID_GATE_NAMES`) or a `post_review: skip` flag that no code writes; `pre_flight_review` flag likewise has no writer. The `closed` state invariant is unsatisfiable by the shipped toolchain. Fix: add `sprint_review` to `VALID_GATE_NAMES` and record it in close_sprint, or drop the invariant and the two flag predicates.

**5. critical / correctness — `hook_handlers.py:25-27` + `state_db_class.py` (`init()` in every method, e.g. 194, 223, 279)** — `get_project()` roots at `Path.cwd()` with no upward discovery, and **every StateDB read auto-creates a schema'd empty DB at whatever path it's given**. Scenario: hook fires with cwd in a subdirectory → phantom `.clasi/.clasi.db` created there → OOP off, lock invisible, tier `""` → guards fail open silently, and stray DB files seed future confusion. Fix: upward root discovery; reads return "absent" when DB file doesn't exist instead of creating it.

**6. major / correctness — `state_machine/predicates/project.py:76-79`** — `is_any_sprint_ticketed` queries DB phase `"ticketed"`, but the DB phase vocabulary contains only `"ticketing"`; no writer ever stores `"ticketed"`. The project machine's `enter-sprint` transition is permanently reported blocked. The unit test can't catch it because it stubs the reader to agree with the predicate (`test_predicates.py:261`). Fix: use `"ticketing"`, and add a test asserting every phase string referenced by predicates exists in `ArtifactGraph.phases()`.

**7. major / correctness — `state_machine/predicates/sprint.py:36-38,49-51`** — Gate predicates check `sprint_gate(...) is not None`, so a gate recorded as **failed** satisfies `is_architecture_review_recorded` and `is_pre_flight_satisfied`, while `StateDB.advance_phase` requires passed/skipped (`state_db_class.py:303`). Two gate semantics for the same row. Fix: predicates check `result in {"passed", "skipped"}`.

**8. major / correctness — `ticket.py:142-156` + `artifact_tools.py:1060` vs `ticket.yaml:111-112`** — Moving a ticket to done and setting `status: done` are two separate operations no single code path performs together; the YAML action doc claims one operation does both. Fix: `move_to_done()` sets `status="done"` in the same call; `reopen()` already does the converse correctly.

**9. major / correctness — `sprint.py:195-204` + `status/reader.py:549-575,720-733`** — `list_tickets`, `all_tickets_done`, and `ticket_count` glob `tickets/*.md`, which matches `<ticket>-plan.md` companions (supported by `move_to_done_with_plan`, `ticket.py:158`). A plan file left in `tickets/` makes `all_tickets_done` False and inflates `ticket_count`. Fix: exclude `*-plan.md` in one shared helper used by all three.

**10. major / simplicity — `sprint.py:496-501` (also `issue.py:67-84,86-111`)** — Non-transactional dual writes: `detail_promote` writes frontmatter then advances the DB; failure between the two leaves permanent disagreement with no reconciler. `Issue.move_to_done` does rename + up to three separate full-file rewrites. Fix: one writer function per transition performing file+DB together, raising loudly on partial completion.

**11. major / correctness — `sprint.py:104-109`** — `Sprint.phase` swallows every DB exception (`except Exception: pass`) and silently falls back to directory inference; a corrupt or wrong-path DB reports "unknown" instead of failing, and a *reachable* DB with a stale phase wins over the `done/` directory. Fix: narrow to "sprint not registered", log everything else.

**12. major / correctness — `frontmatter.py:90-96,125-129`** — Body location uses `content.find("---", 3)` (not line-anchored): any `---` inside a frontmatter value mis-slices the body, and the next `update_frontmatter` round-trip writes the corruption back. Also `_write_document` uses non-atomic `write_text` (partial write → `MalformedFrontmatterError` → `list_sprints` silently drops the sprint, `project.py:416-418`) and `yaml.dump` rather than `safe_dump`. Fix: use `python-frontmatter`'s serializer; temp-file + `os.replace`.

**13. major / correctness — `project.py:32-50`** — `_load_config` returns `{}` on *any* exception including `YAMLError`; a corrupt `config.yaml` silently reroutes `db_path`, `paths`, `sources`, `protected_paths`, design opt-in to defaults — config corruption manifests as unrelated state/guard misbehavior. Fix: distinguish missing (fine) from corrupt (log loudly; fail closed for guard-relevant keys).

**14. major / quality — `artifact_tools.py:855` + `.claude/rules/clasi-artifacts.md`** — `list_sprints` documents status values "planning, active, done" that no writer produces, and the checked-in rule instructs agents to call `list_sprints(status="active")` — always `[]`, so the "confirm you have an active sprint" check is vacuous. Fix: fold into single-vocabulary cleanup.

**15. minor / simplicity — `state_db.py` (whole file)** — 200 lines of pure delegation: 21 wrappers each re-instantiating `StateDB`, plus a second lazy-`PHASES` shim. Fix: migrate the ~7 src callers to `project.db.<method>()` and delete the module.

**16. minor / speed — `state_db_class.py` (all methods) + `project.py:348-393` + `status/reader.py`** — Every StateDB call opens two connections and re-runs the 6-table `CREATE TABLE` script plus `PRAGMA journal_mode=WAL`. `ClasiStateReader` calls `project.get_sprint()` inside ~8 methods, and `get_sprint` parses **every** `sprint.md` per call — one status build is O(sprints × predicates) full-file YAML parses. Fix: memoize `get_sprint` per reader instance; make `init()` one-time-per-instance.

**17. minor / correctness — `state_db_class.py:461-513`** — `rename_sprint` flips `PRAGMA foreign_keys` off/on and relies on an unenforced comment instead of checking phase or updating `execution_locks`/`recovery_state`. Fix: assert phase ∈ {roadmap, planning-docs}.

**18. minor / quality — `state_db_class.py:605-613,845-854`** — `get_recovery_state`/`get_oop` mutate (DELETE + COMMIT) during reads, including on caller-owned connections; report via `print(..., file=sys.stderr)`. Document on `connect()` at minimum.

**19. minor / simplicity — dead/vestigial code** — `Sprint.create_ticket` auto-link reads dead `todos` key (`sprint.py:248`) so it never fires; `contracts.validate_return`/`_extract_json_from_text` have no src callers; `Sprint.usecases`/`technical_plan`/`architecture` properties obsolete under single-doc model (`sprint.py:122-136`); `reader.reopen_requested` + `reopen_requested` frontmatter flag have no writer (`reader.py:712-718`).

**20. minor / quality — tests** — `test_sprint.py` (115 tests) covers OO wrappers but nothing exercises archive+DB interplay, `merge_branch`, or the frontmatter-status vocabulary; state-machine tests stub readers that echo whatever phase string the predicate asks for, so vocabulary mismatches are structurally undetectable. Missing: one integration test that drives a sprint through the real writers (create → detail → gates → tickets → close) asserting machine state, frontmatter status, and DB phase agree at every step — would have caught findings 1, 2, 3, 4, 6, 8.

## Top structural recommendations

1. **Collapse sprint-stage state to one vocabulary with one writer.** DB phase (or machine state — pick one) authoritative; frontmatter `status:` derived at write time through a single `set_sprint_stage()` updating DB + frontmatter together. Dissolves findings 2, 4, 6, 14 and most drift-detector noise. Highest payoff per line changed.
2. **Make `close_sprint`'s state update infallible and loud.** Transactional `force_close` (phase=done, lock deleted), failure reported in tool result. Single most likely source of "tool useless until fixed" lockups (~30 lines).
3. **Add the writer-to-reader integration test** (real writers, real DB, three-way agreement per lifecycle step). Converts vocabulary/wiring drift from "weird runtime bug" to "red test."
4. **Fix `get_project` root discovery and stop creating DBs on read.** Walk upward; reads return "absent" when DB missing. Addresses silent fail-open guards and phantom-DB seeding.
5. **Decide what the state machine is and simplify to it.** Codify "most-advanced match wins", delete the AmbiguousStateError-message parser, delete or wire up unsatisfiable/writer-less predicates (`is_review_satisfied` flags, `is_tests_passing`, `is_reopen_requested`).
